# دفتر الغياب — School Attendance Desktop

**مشروع حقيقي لبرنامج سطح مكتب متعدد الأنظمة يعمل دون اتصال بالإنترنت**: خلفية Rust، قاعدة بيانات SQLite، واجهة HTML/CSS/JavaScript عربية باتجاه RTL داخل Tauri v1.

> **حالة التسليم:** هذه حزمة **سورس كود** وليست ملفات تثبيت مبنية. جرى فحص تركيب ملفات HTML وJavaScript وتهيئة المشروع، **ولم يُجرَ تجميع Rust أو تشغيل واجهة سطح المكتب أو اختبار Windows 7 أو macOS فعلياً في بيئة الإنشاء**. يتطلب تحويل المشروع إلى EXE أو APP عملية بناء على النظام المستهدف. وقد يلزم تعديل تبعيات قديمة بعد الحصول عليها من الإنترنت. لا تعتمد على المشروع في حفظ البيانات المدرسية الفعلية قبل تجربة نسخة مبنية واختبار النسخ الاحتياطي.

## الميزات

- صفوف وشعب متعددة؛ إضافة وتعديل وحذف.
- طلاب مع الاسم والرقم والملاحظات ونوع الدوام **اعتيادي / انتساب**.
- طالب الانتساب **معفي من الدوام**: لا يظهر في شبكة الغياب ولا يطلق التنبيهات. تغيير نوعه إلى انتساب لا يحذف سجلّه القديم، ويمكن إعادته اعتيادياً.
- دفتر يومي لكل شعبة وتاريخ، مع اختيار **عدد دروس ذلك اليوم من 1 إلى 20**.
- جميع الخانات **حاضر ✓** افتراضياً. اضغط الخانة للتبديل بين **حاضر / غائب / مجاز**، أو غيّر اليوم كاملاً للطالب، أو كل الشعبة دفعة واحدة.
- الحفظ الجماعي في عملية SQLite واحدة (transaction)، مع إعادة تحميل سجل أي تاريخ وتعديله؛ إمكانية حذف سجل اليوم للشعبة.
- عدد الدروس = يوم مكافئ قابل للتعديل (الافتراضي **5**). غياب 2 درس = **0.40** يوم مكافئ؛ إجازة الدرس لا تحتسب غياباً.
- تقارير ضمن نطاق السنة الدراسية المحدد (بداية ونهاية قابلة للتغيير). تصدير **CSV UTF-8 مع BOM** لتوافق Excel العربي.
- قواعد تنبيه مستقلة قابلة للإضافة والتعديل والإلغاء: **اسم، لون، حد، أيام أو دروس، المقارنة أكبر من أو أكبر/يساوي، تفعيل وتعطيل**. القاعدة الافتراضية: **تجاوز 8 أيام مكافئة**.
- عطل مدرسية بالأيام تمنع تسجيل دوام على يوم عطلة؛ إن كان اليوم مسجلاً، احذف سجلات الدوام من جميع الشعب قبل إعلانه عطلة.
- نسخة SQLite احتياطية واستعادة من داخل البرنامج؛ موقع البيانات في مجلد بيانات التطبيق لدى النظام.
- لا تسجيل دخول، لا خادم، ولا اشتراك ولا طلبات شبكة من البرنامج نفسه.

## الحصول على ملفات EXE و APP باستخدام GitHub Actions

أضيف workflow في `.github/workflows/build-desktop.yml` لبناء ملف Windows EXE وتطبيقي macOS (Intel وApple Silicon) على أنظمة التشغيل الأصلية. الخطوات العربية المفصّلة: `BUILD_BINARIES_AR.md`.

**تنبيه:** لم تُنفَّذ مهام GitHub Actions ضمن بيئة تجهيز المشروع، لذا هذه تعليمات إنشاء الملفات وليست ملفات تنفيذية جاهزة أو builds تم اختبارها.

## متطلبات البناء

1. تثبيت Rust عبر [rustup.rs](https://rustup.rs/) مع الإصدار **1.77.2**. للاستفادة من تحديثات أدوات البناء يمكنك تثبيت أحدث إصدار أيضاً.
2. تثبيت `tauri-cli` **النسخة الأولى** وليس v2. يستخدم ملف المشروع Tauri 1.8.3. مثال: `cargo +stable install tauri-cli --version 1.6.3 --locked` (بعد تثبيت stable).
3. **ويندوز:** تثبيت Visual Studio Build Tools مع workload "Desktop development with C++" وتثبيت WebView2 runtime مناسب للجهاز.
4. **ماك:** تثبيت Xcode Command Line Tools باستخدام `xcode-select --install`.
5. يلزم اتصال بالإنترنت **عند تنزيل الأدوات والتبعيات لأول مرة**، وبعد البناء يمكن للبرنامج العمل دون إنترنت.

**بناء وتشغيل المشروع من جذر المجلد:**

```bash
rustup toolchain install 1.77.2
rustup toolchain install stable
cargo +stable install tauri-cli --version 1.6.3 --locked
cargo +1.77.2 tauri dev
cargo +1.77.2 tauri build
```

تُوجد سكربتات مساعدة داخل `scripts/`، مع ملاحظة أن Rust 1.77.2 لا يضمن أن جميع **التبعيات المنقولة** التي ستُختار اليوم ما زالت متوافقة معه. يمكن إعداد `Cargo.lock` بأداة حديثة مع إجبارها على اختيار إصدارات متوافقة مع MSRV، ثم مراجعة التبعيات التي لا تزال ترفض البناء. **لم نرفق Cargo.lock** لأنه لا يمكن تنزيل dependencies والتحقق منها في بيئة إنشاء المشروع.

### ويندوز 10 و11

بعد البناء على ويندوز انظر في:

```text
src-tauri/target/release/school_attendance.exe
src-tauri/target/release/bundle/
```

للتوزيع يُفضّل أخذ EXE من مثبت Tauri الموجود بمجلد `bundle` واختبار تشغيله على جهاز نظيف. قد تحتاج في ويندوز 10 القديم لتثبيت WebView2 runtime.

### ويندوز 7 — تحذير توافق مهم

توقفت أدوات Rust الحديثة عن اعتماد ويندوز 7 هدفاً قياسياً بدءاً من Rust 1.78، كما أن WebView2 الحديث لم يعد يعمل على Windows 7. لأجل ذلك اختيرت **Rust 1.77.2 + Tauri v1 + Windows7-compat**. <https://blog.rust-lang.org/2024/02/26/Windows-7/>

**ما يلزم كي يعمل الإصدار المبني على ويندوز 7:**

- جهاز بنظام Windows 7 SP1 (64-bit)، مع حزم تحديثاته الضرورية و WebView2 Runtime **109** المتوافق، والذي لم يعد يتلقى تحديثات أمنية.
- تم ضبط `webviewInstallMode: skip` حتى **لا** يحاول المثبت تشغيل مثبت WebView2 الحديث غير المتوافق مع ويندوز 7. لذلك يجب تجهيز runtime بشكل منفصل **قبل تشغيل التطبيق**. إذا لم يكن موجوداً لن تعمل الواجهة.
- تجميع نسخة خاصة بويندوز 7 باستخدام Rust 1.77.2 على جهاز بناء ويندوز مناسب، وفحص التبعيات والتأكد عملياً من تشغيل EXE على Windows 7 SP1.

**لا يمكن ضمان التوافق قبل اختبار النسخة النهائية على ويندوز 7.** استمرار استخدام هذا النظام القديم يحمل مخاطر أمنية بسبب توقف التحديثات. يمكن لمدير النظام استخدام نسخة أحدث للأجهزة المتصلة بالإنترنت.

### macOS — Intel / Apple Silicon

على جهاز ماك، شغّل `bash scripts/build-macos.sh` بعد تجهيز الأدوات. على MacBook بمعالج M1/M2/M3/M4 سيُبنى إصدار Apple Silicon الأصلي. لبناء Intel انتقل إلى جهاز Intel أو استخدم أدوات target المناسبة. سيظهر التطبيق وملف `.app` في مسار `target/release/bundle/macos`؛ توزيعه لأجهزة خارج جهاز البناء قد يتطلب توقيعاً وnotarization من Apple.

## كيفية الاستخدام

1. افتح **الصفوف والشعب** وأنشئ الصفوف مثل: الأول المتوسط، الخامس العلمي، الخامس الأدبي، ثم الشعب أ، ب.
2. افتح **الطلاب**، اختر الصف والشعبة وأدخل الاسم، أو انقر **إضافة عدة طلاب** للصق قائمة الأسماء (اسم في كل سطر). حدد نوع الدوام.
3. افتح **تسجيل الحضور**، اختر الصف والشعبة والتاريخ، وعدد الدروس. جميع الخانات **حاضر**؛ انقر على خانات الغياب أو الإجازة أو اختر "طوال اليوم" ثم **حفظ الغيابات**.
4. افتح **التقارير** لعرض مجموع الدروس وأيام الغياب والتنبيهات في السنة الدراسية، ثم صدّر تقرير Excel CSV.
5. افتح **قواعد التنبيه** لتغيير الحد من 8 أيام إلى أي قيمة أو إضافة إنذارات متعددة بألوان مختلفة.
6. افتح **الإعدادات والنسخ** لتعديل الدروس/اليوم، السنة الدراسية، وإنشاء نسخة SQLite احتياطية.

## قاعدة البيانات والأمان

- قاعدة بيانات واحدة باسم `attendance.sqlite3` داخل مسار بيانات التطبيق، مثال Windows `%APPDATA%/com.school.attendance` أو المجلد الذي يحدده Tauri بحسب معرف التطبيق، ومجلد دعم التطبيقات في macOS.
- **SQLite غير مشفر**: أي مستخدم لديه صلاحيات قراءة الملف يستطيع الاطلاع على أسماء الطلاب؛ احمِ حساب الجهاز ونسخك الاحتياطية. يوصى باستخدام تشفير القرص على مستوى نظام التشغيل.
- الحذف متسلسل بواسطة foreign keys؛ حذف طالب أو شعبة أو صف يحذف سجلاته نهائياً، والاستعادة من نسخة احتياطية هي وسيلة استرجاعها.
- لا تضع نسخة قاعدة البيانات الحية على مشاركات Dropbox/iCloud/OneDrive دون آلية مزامنة/نسخ مناسبة؛ استخدم وظيفة النسخ المدمجة ثم انقل النسخة الناتجة.

## ملاحظات عن الحساب

- **أيام الغياب المكافئة = دروس الغياب في السنة ÷ عدد الدروس المعتمد لليوم.** ليست بالضرورة عدداً صحيحاً من أيام التقويم الفعلية.
- **الغياب والإجازة حالات لكل درس**؛ الإجازة لا تدخل في حساب تنبيهات الغياب.
- تغيير "عدد الدروس المعتمد لليوم" يُعيد حساب كل التقارير بأثر رجعي (مع بقاء الحضور المسجل كما هو).
- تعديل تاريخ بداية ونهاية السنة يعيد احتساب التقارير والتنبيهات لهذا النطاق، دون مسح البيانات السابقة.
- لا يجري تسجيل أيام السبت والجمعة تلقائياً: يتم تسجيل الدوام فقط عندما تختار تاريخاً وتضغط حفظ. ويمكن إضافة العطل رسمياً في قسم العطل.

## الاختبارات

اختبارات قواعد الأعمال في نهاية `src-tauri/src/store.rs`:

```bash
cd src-tauri
cargo test
```

ولفحص سلامة ملفات الواجهة والبنية دون Rust:

```bash
python3 tests/check_project.py
node --check ui/app.js
```
